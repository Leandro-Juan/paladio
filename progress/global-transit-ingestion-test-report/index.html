    Global Transit Ingestion Test Report¶

    Execution Date: October 29, 2026
    Pipeline Specification: PLAN.md
    Status: COMPLETE (All 11 verification steps executed and passing)

    1. Executive Summary¶

    The Global Transit Ingestion pipeline has been overhauled in strict adherence to the Zero Mock Data, No Fabricated Fallbacks invariant.

    Key architectural achievements: 1. Total Elimination of Hardcoded & Synthetic Data: - Completely deleted compile_tokyo_transit.py. - Removed all synthetic idx * 120 fallback time generation in transit_derivation_service.py. Replaced with mathematical linear interpolation bounded by known timepoints and explicitly tagged with is_interpolated = True. - Replaced hardcoded if city_lower == "tokyo" checks in fare_resolver.py and odpt.py with dynamic supports_city resolution. - Replaced salted abs(hash(...)) in ingest_transit_pois.py with deterministic SHA-256 integers. 2. City Identity & Unicode Standardization: - Implemented standard city_key = {ascii_slug}-{iso2}-{geonames_or_wikidata_id} in city_key.py. - Fuzz-tested with 5,000 random Unicode strings and salt independence checks (PYTHONHASHSEED). - Disambiguated collisions (e.g. cordoba-ar-3860259 vs cordoba-es-2519240, birmingham-gb-2655603 vs birmingham-us-4049979). 3. Multi-Source, Multi-Feed Resolver & Set Cover: - Upgraded gtfs_resolver_service.py with Unicode-aware NFKC casefolding, antimeridian coordinate wrapping, and corrupt (0,0) bbox rejection. - Greedy set cover for multi-operator cities (returning metro, commuter rail, and municipal bus feeds). 4. Coverage Ledger & Global CLI: - Added transit_coverage table and extended TransitCacheStatus with UNAVAILABLE, PARTIAL, STALE. - Built transit_coverage_report.py exporting coverage_report.csv and populating database ledger with zero exceptions.
