PALADIO CORE ENGINE - FUTURE IMPROVEMENTS & TODO

The "Free" Idle Time Problem

Problem: The engine currently shifts arrival_time = earliest_time if arriving early, treating idle waiting time as "free" regarding score and cost.

Solution Options:

Hard constraint: Add max_idle_time to configuration (e.g., max 45 minutes). If exceeded, continue.

Soft constraint: Penalize current_score subtracting points based on waiting time (e.g., $-0.5$ points per 15 minutes lost).

Fatigue and Travel Pacing

Problem: The greedy-like approach can chain 13 hours of continuous high-density activity without rest, causing exhaustion.

Solution: Implement a decay function. Add continuous_active_time to SearchState. If continuous time without visiting a rest node (like a BAR, park, or HOTEL) exceeds a threshold (e.g., 4 hours), multiply subsequent intensive POI scores by a penalty factor (e.g., $score \times 0.6$).

Unrealistic Meal Grouping

Problem: Current boolean flags and deadlines allow unrealistically close meal times (e.g., breakfast at 12:00, lunch at 12:30).

Solution: Replace booleans with last_meal_time or an array of meal timestamps in SearchState. When evaluating a RESTAURANT, enforce arrival_time - last_meal_time >= MIN_MEAL_SPACING (e.g., minimum 3 hours separation).

Diminishing Returns from Monotony

Problem: Maximizing absolute score can lead to repetitive itineraries (e.g., 4 museums in a row).

Solution: Track category visit counts (via small array or bit manipulation). If 2 attractions of the same type have already been visited, apply a marginal utility decay curve to the score of the third to enforce diversity.

Return to "Base of Operations"

Problem: end_node_type forces a category (e.g., any HOTEL), but not the specific starting hotel where luggage or base is located.

Solution: Add an explicit std::optional<int> end_node_index in OptimizationConfig to force the final node of current_path to match the starting node, adding the final return transit cost and time.
